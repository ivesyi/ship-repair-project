# 船舶修理预成本分析：可行性交流与小范围验证方案

交付日期：2026年9月15日（周二）。编制日期：9月12日。供领导、业务与技术部门讨论。

## 1. 本次希望解决的问题

先用一个可以核对结果的维修案例，说明系统怎样利用历史资料辅助编制工程明细、材料需求、工时与预成本，再共同决定是否进入小范围离线验证。

贵方目前处于调研阶段，尚无现成算力平台。正式环境要求局域网运行、业务数据不出内网，国产化及供应主体要求需由贵方明确具体准入范围。此次交流不要求先采购设备。

## 2. 系统怎样帮助工程师

贵方现有流程是：收到初步工程明细 → 实船勘验 → 对照历史目标成本船预审 → 编制本次工程明细书 → 安排人工、采购和施工。系统嵌入其中的“历史对照、差异整理、测算和初稿编制”环节。

工程师输入本次初步工程明细与勘验结果，并可指定历史参照船。系统列出哪些项目沿用、增加、减少或需要进一步确认，按已确认的数量、价格和工时规则计算费用，生成供工程师审核的初稿。

模型负责读懂文字、提取字段、组织差异说明；资料库提供案例、工艺与价格依据；计算程序负责算术；工程师确认工艺适用性与最终结果。历史资料不会变成算力，接入资料也不等于重新训练模型。

## 3. 周二展示的完整案例

采用明确标注为虚构的10套维修记录和第11套新需求，不使用贵方真实资料。附件提供具体数据、计算规则和预期结果。

展示顺序：

1. 打开历史记录，说明字段和来源编号；由工程师指定参照案例，再展示其他候选为何适合或不适合。
2. 输入本次船型、修理等级、初始工程明细及已知勘验结果。
3. 展示差异表、材料清单、工时和预成本小计，每行能回到对应输入或规则。
4. 修改一个勘验数量，观察明细与金额同步变化。
5. 新增一项缺规格、缺单价的需求，系统列入待确认项，明确总成本尚不完整。
6. 工程师审核后导出带版本与审核状态的方案初稿。

交付成果为：案例输入、差异表、工程明细初稿、材料及人工测算、待确认项、引用依据和修订记录。演示案例不构成实际维修工艺或施工依据。

如演示环境经过测试，可展示现场模型操作；若尚未完成，则使用明确标注的流程样张讲解。流程样张、预录结果、现场模型输出三者分别标明，只有真实运行记录可以作为模型测试证据。

## 4. 先验证什么，再决定设备

| 阶段 | 工作与产出 | 下一步条件 |
| --- | --- | --- |
| 周二可行性交流 | 虚构案例、方案样张、候选技术路线、费用组成及验证任务单 | 业务方认为流程值得验证，明确联系人 |
| 小范围离线验证 | 在允许的设备与环境中运行一个船型、一个修理等级、3—5类典型项目；样本数量由资料完整性决定 | 业务专家认可输出，技术方完成离线与容量验证 |
| 试点建设 | 工艺整理、资料接入、界面与审核流程、部署和培训 | 按双方约定的试点验收标准通过 |
| 扩展 | 依据新增业务、资料量和负载评估增量工作 | 单独确认范围与投入 |

离线验证可考虑我方已有测试设备、供应商借测设备或贵方批准的临时设备；来源、费用、型号、运输及入场条件尚待落实。没有符合要求的测试环境时，先交付测试清单，不声称已经证明本地效果。

正式本地化范围包括模型、文件解析、检索/向量模型、数据库、业务工具、日志与界面等全部运行依赖。测试需覆盖断外网后的启动、资料读取、推理、计算和导出；还需由技术方核查外联尝试、更新机制及权限。仅将模型放在本地不足以证明全系统离线。

## 6. 工艺与资料整理是独立工作包

至少十年的电子资料是良好起点，但仍需检查格式、完整性、价格时点和工艺适用条件。

一期先整理选定范围：已有结构化内容校验后接入；文件中的内容转成工艺卡并请专家审核；主要依赖经验的部分通过具体案例与专家访谈补充。工艺卡包含适用范围、触发条件、工程项目、材料规格与单位、数量和工时的确定方式、质量要求、来源、版本及审核人。

尚无依据的内容保留为待确认项。全量十年资料整理、OCR批量处理、历史价格治理及ERP集成均需样本评估后另定范围。

## 7. 费用如何说明

会上曾以“10人使用”为例，口头讨论约20—30万元硬件量级，贵方表示效果成立时可以考虑。这不是预算批准，也不是整套软件项目报价。注册用户数与同时运行任务数需要分别确认。

| 费用项 | 周二说明方式 | 核价依据 |
| --- | --- | --- |
| 测试设备或演示资源 | 已有资源优先；租用或借测费用单列 | 型号、使用时长、交付范围和实际报价 |
| 正式硬件 | 给出配置路线和询价要求；有书面报价才列价格及有效期 | 准入型号、实测任务负载、保修、含税及供货条件 |
| 软件与实施 | 与硬件分列 | 输入格式、流程、接口、权限、部署工作量 |
| 工艺和资料整理 | 单列 | 样本页数、表格复杂度、工艺项目数、专家投入 |
| 培训、运维与维保 | 单列年限与响应范围 | 交接内容、服务期限、更新及故障责任 |

配置路线分为“满足准入的最小验证设备”和“通过实测后确定的正式设备”。若贵方允许通用算力，再比较通用GPU路线；如要求国产CPU、加速卡和操作系统，则在该范围内询价、适配和测试。不能将消费级英伟达方案当作已合规的默认采购项。

周二若未拿到有效报价，应明确写“待核价”，保留会上20—30万元作为历史讨论记录，不能用未经验证的5—6万元起步价替代承诺。正式报价须注明硬件、软件、资料、适配、维保是否包含，避免重复计费。

## 8. 如何验收小范围验证

以下为建议口径，需与业务及技术负责人确认后成为验收约定。

| 检查项 | 观察方式 |
| --- | --- |
| 字段与差异 | 专家预先标注必需字段、沿用/增减项目；记录遗漏、误增与错误适用 |
| 工艺与来源 | 每项建议能回到资料或规则；无依据项明确待确认 |
| 计算 | 在输入、单位及规则确定时逐行与独立计算结果核对；核对项应无差额 |
| 缺失与修改 | 缺规格/单价时不补造；修改数量后重算并保留版本 |
| 工作价值 | 与人工完成同一任务比较耗时、修改量和可采用内容，由工程师判断 |
| 容量 | 固定模型版本、量化、输入长度与输出上限，测1/3/5/10个同时任务的耗时、失败率和资源占用；未完成档位明确标记 |
| 离线 | 在批准环境中断外网运行完整流程，保存技术检查记录 |

不预先承诺通用“准确率”、10人实时并发或某张卡覆盖全部场景。通过演示只说明演示任务通过；生产可用性需在拟交付环境另验。

## 9. 后续维护与可交接

试点交付约定应包括源码、模型与依赖清单及许可、版本/校验信息、安装包和配置、数据结构、规则库、提示词、测试集、备份恢复与升级回退说明、部署运维手册及培训。替换团队需具备相关能力，并在约定环境完成一次交接演练。

模型升级先回归测试再安排上线；是否重建索引取决于检索模型或数据结构是否变化。新增业务要重新评估数据、规则、权限和容量。
