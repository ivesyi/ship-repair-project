## 2. 最推荐的模块组合

| 模块 | 首选技术 | 本轮验证 |
| --- | --- | --- |
| OCR与表格 | PaddleOCR的PP-StructureV3文档解析流程 | 图片工程单转表格/字段，并保留页码、坐标和原文供核对 |
| 语音转写ASR | FunASR＋Paraformer中文识别 | 先按住说话、结束后识别；转写后用户确认再修改工程单 |
| 语音播报TTS | Fun-CosyVoice3-0.5B-2512 | 用获许可的示例音色或本人授权声音，播报已核对的摘要 |
| 视频检测 | PaddleDetection的PP-YOLOE行人检测＋ByteTrack跟踪 | 单路视频/摄像头区域进入、离开和停留事件 |
| 业务中枢 | 沿用Qwen3-Coder＋Qwen-Agent＋Python计算＋SQLite | 接收OCR/ASR字段或视频事件，展示引用、待确认项、成本和记录 |

## 3. 主演示：拍单据、说勘验、看重算、听解释

1. 把既有虚构N11初始工程明细制作成印刷体表格图片：P01数量3，P02面积20㎡。
2. OCR读取，左侧显示原图与定位，右侧显示字段。核对规格、数量、小数、单位；缺失和不确定内容交用户确认，不静默写入。
3. 说：“表面处理面积改为三十平方米，泵组件仍为三个。”先展示识别文字和拟修改字段，确认后产生N11 v2。
4. Python计算输出已知项4800元；与v1的3900元对比增加900元。
5. TTS播报：“已知项目小计四千八百元，比上一版增加九百元，方案待工程师审核。”播报内容来自核对后的结果。
6. 再说：“另有两件阀件，规格和单价暂时不清楚。”系统新增待确认行，不将4800元标作完整预成本。

先验证普通印刷体工程单；手写、倾斜、反光、复杂合并单元格各作为额外测试样本，不提前承诺识别准确率。第一轮采用轮流讲话方式；持续对话、打断、回声消除和嘈杂现场识别后续另测。

## 4. 辅演示：摄像头区域事件看板

使用获准拍摄的自演视频或USB摄像头，画一块虚构工作区域。有人进入时显示检测框、临时轨迹编号、事件时间和截图；停留超过演示阈值（例如5秒）产生一次提示；离开后关闭事件。阈值只是演示规则，不是行业安全标准。

链路：摄像头/视频 → 解码 → 行人检测 → 跟踪 → 区域与持续时间规则 → 事件表 → 页面提示/固定话术播报。Agent可按事件表回答“刚才发生了什么”，不参与逐帧实时判定。

先用短视频跑通，再接USB摄像头；确有网络摄像头时再接RTSP。录像回放标记为回放。云端服务不能直接访问笔记本的USB摄像头：需要浏览器或采集程序发送视频帧，或在本机处理后上传事件；只能采集用户明确允许的演示画面。

检测框出现不等于事件正确：检查同一个人连续停留是否重复告警、短暂遮挡后是否被重复统计、多人同时进出及空场误报。ByteTrack轨迹编号不是人员身份，不做身份识别。安全帽、火焰、裂纹等需要对应类别权重和数据，不能从普通行人模型直接推断可用。

## 5. 云端部署顺序与资源

保留此前LLM服务。OCR、ASR、TTS、视觉服务各用独立环境/容器，通过接口接入，避免把Paddle、PyTorch和推理服务依赖混装。

先逐个测试，再测试合并后的资源峰值。实时视觉与LLM分进程，负载需要时分设备；不能承诺原来给LLM估算的80GB显存配置同时容纳并稳定运行全部服务。验证记录包含模型/版本、显存峰值、输入大小、并发、失败与延迟。

摄像头先单路720p、每秒采样5—10帧作为试验起点；这不是已测性能。分别记录采集、网络、解码、推理、规则和显示延迟，云端端到端延迟不等于模型单帧耗时。测试RTSP断线重连和丢帧，不能把“本地”直接解释为“毫秒级”。

周二优先级：OCR接工程单 → 语音修改与确认 → 短句TTS → 独立视频事件演示。若主业务链尚未跑通，视频作为独立补充，不挤占预成本案例的准备时间。所有运行模式和未通过项如实标记。

## 6. 官方资料

本轮查阅的项目入口：

- [PaddleOCR](https://github.com/PaddlePaddle/PaddleOCR)：PP-StructureV3支持文档结构化解析与细粒度坐标，可用于原文定位。
- [FunASR](https://github.com/modelscope/FunASR)：提供ASR、VAD、标点与流式相关能力；本轮选Paraformer作中文基线。
- [CosyVoice](https://github.com/QwenAudio/CosyVoice)：官方列出Fun-CosyVoice3-0.5B-2512及推理示例。
- [PaddleDetection](https://github.com/PaddlePaddle/PaddleDetection)：提供目标检测及跟踪能力，包含PP-YOLOE和ByteTrack相关实现。
- [ByteTrack](https://github.com/FoundationVision/ByteTrack)：多目标跟踪参考实现。
- [VoxCPM](https://github.com/OpenBMB/VoxCPM)：可作为后续TTS对照；为控制周二准备范围，本轮不同时部署两套TTS。

这些来源用于确认技术入口，不证明已在本项目数据或设备上达到某种效果。
