## 2026-09-14：工作台迁入 Harness 业务插件

执行链路：工作台 → 主服务插件 → 会话控制器创建／复用订单会话 → 专用预设 → 原生订单核算工具 → 已部署千问模型 → 会话事件 → 工作台状态与复核清单。不同订单独立会话，同单重试复用；工具验证会话是否关联所请求订单。业务状态、模型原始回复和格式化回复留在本机；Harness 保留会话日志。金额继续不使用千位逗号。

### 这次实际遇到的问题

1. 主服务插件和 Agent 工具的依赖作用域不同。主插件注入 connection、sessionController；工具入口单独注入 tools，不能要求主服务拥有 Agent 的 tools 服务。
2. 只向仓库 node_modules 安装插件不够。主服务从 Harness profiles/web 解析插件，订单预设从其自身 node_modules 解析。开发配置脚本现为两个位置安装链接。正式离线包必须携带实体依赖，不可依赖开发机绝对路径。
3. Fetch 路由必须明确 requestBody: buffered。遗漏后 GET 被桥接成带流请求体，导致 HTTP 400 和空白窗口。已对页面与操作接口明确配置。
4. 会话控制器 prompt 需要 AbortSignal；遗漏会报 throwIfAborted。已传入请求的取消信号，历史读取也显式传信号。
5. 回复文本位于事件 data.message.content；成功判断必须检查 turn/end 的 reason.kind 和工具返回的 isError。截断、中断及错误不会伪装成完成。
6. 启动时自动打开插件可能早于 Harness 完成认证。改为主窗口就绪后由菜单打开，共享同一 Electron 会话的正常认证；没有关闭或绕过认证。
7. 没有假设 Harness 支持未确认的会话地址参数。工作台内提供真实事件轨迹页，完整会话仍保存在 Harness。

## 2026-09-14：从手填纸单到交付档案

主入口重做为单订单连续流程：导入图片后自动识别 → 人工对照确认草稿 → Agent 调用纸单检查工具 → 人逐项说明疑点 → Agent 调用归档工具 → 下载离线网页档案。图片支持12兆以内单页PNG、JPEG、WebP，尚不支持PDF、多页、语音或视频。

样例图片由图像生成工具生成并标注“模拟演练，非真实订单”，没有真实客户签名。识别与两个工具调用真实执行。样例成功识别船名和三项明细，保留6670.00元原值；模型把合计识别成69166.00元，人工去掉数字字段的元后继续。程序计算70776.00元，列出1610.00元差额、块数与重量、历史单价三项问题。未填写问题说明就归档被拒绝。三项演练说明保存后，Agent完成归档，状态为待正式审批，非采购批准。

新增原图指纹与独立文件保存、识别原稿与人工确认对照、任务事件、问题状态及档案导出。下载的单文件网页已验证包含内嵌原图及中文对照记录，不依赖外网素材。模型仍通过SSH连接AutoDL，不能称为已通过客户现场断网部署。

接入坑：Harness会话控制器的图片输入需要type:image加data、mediaType等编码字段；工具输出使用的attachment引用不能直接作为prompt输入，误用时返回prompt rejected和undefined buffer错误。改用标准编码输入后通过正常附件服务入库与模型调用。模型设置需显式声明text、image输入。

验证：完整回归105个文件905项通过；类型检查与构建通过。单据图像识别、人工确认、检查工具、归档工具以及原生下载对话框均已实机走通。行区域定位为模型估计，不承诺精确。纸单流程尚未连接真实知识库或生产技能发布。
